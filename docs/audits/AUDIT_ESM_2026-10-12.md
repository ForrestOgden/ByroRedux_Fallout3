## Findings

### HIGH

#### ESM-2026-10-12-D2-01: the `WTHS` `DIFF` value walker recurses with no depth bound, so a hostile `RDIF` blob aborts the process with a stack overflow
- **Severity**: HIGH. An untrusted-input reader that can be made to abort (`_audit-severity.md`: "Untrusted-input reader: panic ... HIGH"). The failure is a stack overflow, not a catchable panic.
- **Dimension**: Sub-Record Byte Accounting (untrusted-input discipline of the new decoder)
- **Record / Sub-record**: `WTHS` / `RDIF` (also `REFL`)
- **Location**:
  - `crates/plugin/src/esm/records/weather_settings.rs:370-421`: `skip_diff_value`
  - `:343-364`: `collect_diff_indices`, the entry point
  - `:392`: struct recursion
  - `:419`: `Ref` recursion
- **Status**: NEW. Introduced by #5514 (`f0f8dceef`, 2026-10-11). Not in the open-issue snapshot or any prior audit. #5643 is a different recursion (Story Manager tree build) and #5627 is the unrelated `WTHS` value-reader tracker.
- **Description**: #5514 replaced the flat index read with a recursive value skip that mirrors `crates/sfmaterial/src/reader.rs`. Two of its arms recurse on file-controlled data:
  - A non-user class field (a "struct") opens a nested diff-pair stream and recurses into each field's own type.
  - A `Ref` field reads a target type id and recurses into it.

  The class table is decoded from the same blob (`CLAS` chunks with arbitrary `type_ref`s), so a class whose field 0 names the class itself is legal to the parser. Every nesting level consumes only 2 bytes (the field index) or 4 bytes (a `Ref` target), so the recursion depth is bounded by the payload length, not by any cap. The sibling reader that this code claims to mirror carries `MAX_NESTING_DEPTH = 64` (`sfmaterial/src/reader.rs:20`, enforced at `:438-450`). The port dropped the guard.
- **Evidence** (release build, 1.96 toolchain, the real `parse_bgs_reflection`, scratch probe `/tmp/audit/esm/probe/src/main.rs`):
  - Blob: `STRT "C\0"`, one `CLAS` with `flags=0` and one field whose `type_ref` is the class's own name offset (0), and a `DIFF` payload of `type_ref = 0` followed by N repetitions of the u16 `0x0000` (each repetition is "field 0 present, value is the same struct again").
  - N=1 000 and N=30 000 on a 2 MiB thread: `ok`, `diff_field_indices = None` (the walk ends cleanly at the end of data).
  - **N=100 000** (200 KB payload) on a 2 MiB thread, which is the default stack of the rayon walk workers that run the plugin walk (#3813): `thread has overflowed its stack / fatal runtime error: stack overflow, aborting`.
  - N=1 000 000 (2 MB payload) on an 8 MiB thread (the main thread's stack): the same abort.
  - A sub-record payload over 64 KiB needs the `XXXX` extended-size override, which `read_sub_records` supports (`reader.rs:973-989`).
- **Impact**: Any Starfield plugin, or any plugin that carries a `WTHS` record, can kill the engine at load with an abort (not a recoverable error) before any cell loads. Vanilla data never trips it (163/163 real `RDIF`s decode, 0 `None`, via `parse_esm`), so this is a hostile-mod and corrupted-file hardening gap, not a vanilla bug. Blast radius is one record kind, but the consequence is process death, which the severity table puts at HIGH for untrusted-input readers.
- **Related**: #5514 (introduced it), #5364 (the `WTHS` decode), #5627 (the value-reader follow-up, which will reuse these helpers and inherit the problem), the 10-09 report's "parser discipline" Dim 2 notes. The same class is guarded elsewhere by `MAX_GRUP_NESTING_DEPTH` (Dim 1) and the SM walk cap noted in #5643.
- **Suggested Fix**: thread a `depth: usize` through `skip_diff_value` / `collect_diff_indices` and return `false` (the walk already treats `false` as "decline, leave `diff_field_indices` unset") once it passes a cap equal to `sfmaterial`'s 64. Pin it with a unit test that builds the self-referential class and asserts `diff_field_indices == None` without overflowing. A `Ref` chain test should cover the other recursion edge.
