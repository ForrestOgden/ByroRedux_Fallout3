- **Dimension**: 4 (cell expansion / REFR overlay), with Dim 2 reach (the swapped BGSM is never merged).
- **Location**: `byroredux/src/cell_loader/spawn/mesh_instance.rs:113-143` (`resolve_mesh_paths_with_pre_merge`: `current` from

  `crates/nif/src/import/material/dedicated_shader.rs:144` + `crates/nif/src/import/mesh/material_path.rs:20-26` (the NIF

- **Status**: NEW. Searched open and closed: "MSWP", "material swap", "XMSP", "FNAM"; only #971 / #973 / #3242 / #4290 /
  #4400 / #4241 / #5497 (all about shipping or the swap's downstream merge, none about the source-key form).
- **Description**:

  - The two sides have different canonical forms in the shipped data. MSWP `BNAM`/`SNAM` are **bare** (relative to
    `Data\Materials\`): across all seven masters, 9,065 of 9,065 `BNAM` and 9,065 of 9,065 `SNAM` have no `Materials\`

#### FO4-2026-10-12-D4-02: MSWP `FNAM` is the CK object-window "Tree Folder", decoded and applied as a runtime path-prefix filter
- **Severity**: MEDIUM. Currently masked by D4-01 (nothing reaches the filter on real data) and becomes the next failure once
  D4-01 is fixed.
- **Dimension**: 4.
- **Location**: `crates/plugin/src/esm/records/mswp.rs:14-15,77-80,98` (decoded and documented as a "path-prefix filter");
  consumers `byroredux/src/cell_loader/refr.rs:483-492,503` and `byroredux/src/cell_loader/spawn/mesh_instance.rs:116-124`
  (`current.to_ascii_lowercase().starts_with(&filter)`).
- **Status**: NEW. Same class as #5493 (SCOL/PKIN `FLTR` was decoded as a FormID array; it is the CK filter path). Not
  covered by ESM-2026-10-12-D5-01, which concerns the doc text for XPRI / `absorbed_refs` / FLTR / MSWP `CNAM`.
- **Description**: the Creation Kit's Material Swap editor dialog lists "Tree Folder:" (with no runtime semantics) before the
  "Material Substitutions" list (`falloutck-uesp-wiki/(main)/Material Swap.wiki`). The data agrees: an FNAM names the editor
  tree, not a prefix of the swapped materials.
- **Evidence** (all seven masters, bare-to-bare, the most generous reading of the filter): 3,937 MSWP records, 1,482 carry
  `FNAM`, 4,455 `BNAM` in those; only 2,285 (51%) have the FNAM as a prefix; **806 records have every swap rejected**, 133
  more lose some. Examples: `FNAM Interiors\Vault` with `BNAM SetDressing\Vault\VltLight01.BGSM` (the six `0x24030a-0x24030e`
  vault-light swaps); `FNAM Effects` with `BNAM Vehicles\Automotive\Car_Glass01.BGEM`. Under the engine's actual forms the
  filter fails on every record, because the shape name carries `Materials\`.
- **Impact**: after D4-01 is fixed, 54% of FNAM-carrying MSWP records (806 of 1,482) still drop all their swaps, silently.
  The record doc and the "Set on ~53% of vanilla records" comment bake the wrong semantics in for the next reader.
- **Related**: D4-01, #5493, ESM-2026-10-12-D5-01, `mswp.rs:21` (cited there for its stale CNAM line).
- **Suggested Fix**: drop the runtime filter (keep the string for tooling), fix the `mswp.rs` module and field docs, and
  pin it with a unit test that applies a swap whose FNAM is not a prefix of its `BNAM`.
