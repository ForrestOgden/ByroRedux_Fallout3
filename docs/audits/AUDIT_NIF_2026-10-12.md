### LOW

#### NIF-D1-2026-10-12-01: `BSLightingShaderProperty` / `BSEffectShaderProperty` report an opaque-tail length on every game, so `opaque_tail_histogram` is non-empty for every Skyrim / FO4 / FO76 file, against its own "empty for every non-Starfield file" doc
- **Severity**: LOW (telemetry semantics plus a false doc comment; no parse effect)
- **Dimension**: Stream Position (opaque-tail telemetry, #2625)
- **Game Affected**: Skyrim LE/SE (`bsver 83`/`100`) and FO4/FO76 (`bsver 130`/`155`). Starfield is the intended population.
- **Location**:
  - `crates/nif/src/blocks/shader/lighting.rs:1080-1082` (`opaque_tail_len` returns `Some(self.starfield_tail.len())` unconditionally);
  - `crates/nif/src/blocks/shader/effect.rs:354-356` (same);
  - `crates/nif/src/scene.rs:124-125` (the doc: "Empty for every non-Starfield file — only blocks overriding `opaque_tail_len` contribute");
  - consumer `crates/nif/src/lib.rs:505-509`.
- **Status**: NEW
- **Description**: `starfield_tail` is an empty `Vec` unless `read_starfield_tail` captured something, and that only happens for `bsver >= STARFIELD`. But `opaque_tail_len` returns `Some(len)` rather than `None`, and `lib.rs:505` records any `Some`. Every `BSLightingShaderProperty` and `BSEffectShaderProperty` on every game therefore bumps `opaque_tail_histogram[type][0]`.
- **Evidence** (`driftcensus` / `parsecensus`, logs `/tmp/audit/nif/drift.log` and `pc_b.log`):
  ```
  Skyrim SE Meshes1: tails={"BSEffectShaderProperty": {0: 2343}, "BSLightingShaderProperty": {0: 6023}}
  files with a non-empty opaque_tail_histogram: Skyrim LE 17,015 of 17,216; SSE Meshes0 18,609 of 18,862; SSE Meshes1 3,143 of 3,185
  Oblivion / FO3 / FNV: tails={} (their lighting property is the older BSShaderPP family, not the Skyrim one)
  ```
- **Impact**: There is no parse effect. A consumer that follows the documented contract, treating "non-empty tail histogram" as "this file has a Starfield-style opaque tail", gets a false positive on every Skyrim+ file. Each such block also does a histogram bump on the hot parse loop for no signal. The doc is already wrong as written.
- **Related**: #2625 (introduced the histogram), `every_tail_capturing_block_reports_it_and_parse_nif_records_it` (`blocks/shader_tests/starfield.rs`, which pins that the override exists but not that it is gated).
- **Suggested Fix**: Return `Some(len)` only when the block actually captured a tail (`(!self.starfield_tail.is_empty()).then_some(...)`) or when `bsver >= STARFIELD`, so Starfield's real zero-length tails (480,757 blocks) still count. Otherwise, correct the `scene.rs` doc to say "every `BSLightingShaderProperty` / `BSEffectShaderProperty` records its tail length, 0 on pre-Starfield".

#### NIF-D5-2026-10-12-01: Two comments still say Oblivion `LimitedHinge` zeroes `Perp Axis In B1`, which #5537 made false; they sit beside the plain-hinge arm that does still zero it
- **Severity**: LOW (doc rot after a fix)

- **Status**: NEW (follow-through of #5537, closed)
- **Description**: `526cb07d9` changed `LimitedHingeCInfo::parse_oblivion` (`constraints.rs:391-415`) to derive `perp_axis_in_b1 = PerpB2 × AxisB`, and corrected `docs/engine/physal.md:171-177`. ## Verified, not reported

- **`attach_light.rs`** (`c1a99c25e`): exact, case-insensitive match; composes the root→node chain through the same `compose_transforms` as the flat mesh walk; switch/LOD nodes follow only the active child; the Starfield `length_scale` is applied. It carries its own `visited` bitset and a 256-deep cap, so a hostile self-referencing child list terminates (`a_child_cycle_terminates`). Both consumers (`cell_loader/partial.rs:134`, `references/import.rs:160`) run on the main thread, off the stream worker's `catch_unwind` path, and are bounded.
- **`revisit_guard` placement**: it marks a block on first contact even when the caller then drops it as culled or an editor marker, so a repeat reference cannot re-walk it. The 10-09 census found 0 multi-parent children across 128,377 NIFs and 399,033 `NiNode`s, so "each block at most once" changes no vanilla import. FO3, Skyrim LE and FO76 were not in that census; the walker semantics are game-agnostic.
- **#5571 `NiPathInterpolator`**: the composition `path(percent(t))` is correct per the cited reference. All 205 vanilla path interpolators carry percent data. It is bounded by the same `reserve` (span, ceiling, budget). A NaN span degrades to a single filtered sample. Empty rotation/scale keys are safe in the core samplers (`sample_rotation` / `sample_scale` return `None` on empty keys).
- **`BsplineWindow::sample`**: `u` is clamped to `[0, u_max]` over the interpolator's own span, so a disjoint sequence window holds the nearest curve end. The duplicate-time keys this can emit are harmless in `find_key_pair` (`dt > 0.0` guard).
- **#5491 `recv_next_live_request`**: the cancel flag is checked after the batch-memo receive, and the memo is cleared on cancel.
- **Residual, hostile-only (not filed)**: the aggregate B-spline budget is per entry-point call. `import_embedded_animations_with_sequences` makes two calls (the embedded pass and `import_kf`), so one NIF can spend 2 M keys (about 250 MB). A pre-parse cell runs up to 32 such tasks. The earlier ~118 MiB-per-4 KB amplification is gone and only a crafted file can approach this bound, so I judge it acceptable.
- **`opaque_tail` for `BSFaceGenNiNode` / `BSWeakReferenceNode`** (`node.rs:817`, `:1036`): Starfield-only types, so unaffected by NIF-D1-01.
- **#5596 helper swap** (`le_u32_at` / `le_f32_at` / `le_u16_at` in `havok_packfile.rs`, `sse_recon.rs`, `tangent.rs`): `checked_add` makes an offset near `usize::MAX` a miss. In `tangent.rs` the `unwrap_or(0.0)` is unreachable because `blob.len() == expected_size` was checked first.
