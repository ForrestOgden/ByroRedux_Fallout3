### ECS-2026-10-12-D3-01: five hand-rolled `Children` walks duplicate the new `collect_subtree`, and one of them was written 15 hours before it
- **Severity**: LOW
- **Dimension**: 3 — hierarchy traversal
- **Location**: `byroredux/src/cell_loader/unload.rs:65-78` (`player_owned_entities`), `byroredux/src/player_body.rs:441-455` (`descendant_entities`), `byroredux/src/npc_spawn/resumable/runtime.rs:1280-1305` (`subtree_has_skinned_mesh`) and `:1340-1375` (`common_shape_rotation`), `byroredux/src/cell_loader/water.rs:790-808`
- **Status**: NEW
- **Description**: #5513 (`9da80470d`) added `core::ecs::collect_subtree` as "the one shared collector every whole-subtree walk routes through", and moved its existing call sites onto it. Five whole-subtree `Children` walks still carry their own copy of the visited-set-plus-`HierarchyTraversalGuard` loop.
  - `player_owned_entities` and `descendant_entities` are exactly `collect_subtree` (the second minus the root).
  - `subtree_has_skinned_mesh`, `common_shape_rotation` and the water plane scan are `collect_subtree` followed by a per-entity filter.
  - `player_owned_entities` was written in `5a68e983e` (2026-10-10 09:57). Its comment says "Cycle-safe subtree walk, matching `cinematic_retained_entities`", and that function now calls `collect_subtree`.
- **Evidence**: each site has the same shape, for example `unload.rs:68-76`:
  ```rust
  let mut stack = vec![root];
  while let Some(entity) = stack.pop() {
      if !protected.insert(entity) { continue; }
      if let Some(row) = world.get::<Children>(entity) { stack.extend(row.0.iter().copied()); }
  }
  ```
  The ragdoll BFS walks (`ragdoll.rs:715`, `:771`) and `bounds.rs` are different: they interleave per-node work and lock-held queries, so they are not candidates.
- **Impact**: none today, since every copy has a visited set. The risk is that the next copy skips it, which is the failure class #3700, #4572 and #5513 each closed. The hierarchy-walk discipline lives in one place only if the walks use it.
- **Related**: #5513 (closed); the baseline's ECS-2026-10-09-D3-01.
- **Suggested Fix**: route the five sites through `collect_subtree` (the water scan and the two `runtime.rs` walks filter its result). Drop `player_body.rs`'s `HashSet` import if nothing else uses it.

### ECS-2026-10-12-D6-01: `footstep_system` plays no sound at all when `PhysicsWorld` is absent, although its comments promise the default sound
- **Severity**: LOW
- **Dimension**: 6 — `FootstepScratch` / audio adapter
- **Location**: `byroredux/src/systems/audio.rs:274-283` and `:306`
- **Status**: NEW
- **Description**: the surface-material lookup builds one `Option<u32>` per trigger, but the no-`PhysicsWorld` arm returns an empty `Vec`. The play loop then does `triggers.iter().zip(surface_materials)`, which stops at the shorter side, so zero one-shots are played. The comment above it says a trigger "with no solid ground in range ... reads `None` and takes the default sound". The sibling `impact_audio_system` documents the missing-`PhysicsWorld` case as a clean no-op.
- **Evidence**:
  ```rust
  let surface_materials: Vec<Option<u32>> =
      if let Some(pw) = world.try_resource::<PhysicsWorld>() { triggers.iter().map(..).collect() }
      else { Vec::new() };
  ...
  for (pos, surface) in triggers.iter().zip(surface_materials) {
  ```
- **Impact**: none in the shipped engine, because `boot/world.rs:182` always inserts `PhysicsWorld`. It shows up only in a reduced `World` (a headless fixture, or any future physics-less mode), where footsteps vanish and the stride tests that count `scratch.triggers` cannot see it. It also drains `triggers` and discards them without a diagnostic.
- **Related**: #5556 (closed), #5348 (open, a different footstep gate).
- **Suggested Fix**: use `vec![None; triggers.len()]` in the else arm so every trigger takes the default sound, and add a test that runs `footstep_system` with no `PhysicsWorld`. Owner overlap: `/audit-audio`.
